# 生产只读核查工作流

## 目标

在不改变生产数据和外部业务状态的前提下，取得可复核的事实证据，并把技术观察与业务结论分开。

## 步骤

1. **定义问题**：写明店铺、订单、时间范围、目标字段和不在范围内的内容。
2. **确认权限**：确认使用只读账号、允许的系统、环境和查询范围；没有权限时记录 `blocked`。
3. **建立连接**：按 `runbooks/production/database-readonly.md` 建立受控隧道，先验证数据库、账号和事务模式。
4. **采集证据**：使用最小查询集，记录查询意图、时间、结果摘要和限制；结果中隐藏个人数据和秘密。
5. **分层结论**：分别写观察事实、推断、建议、已完成动作和未验证事项。
6. **业务映射**：订单、归因、资格、hold/release、ledger、provider acceptance、invoice/payment、refund/adjustment 分开判断。
7. **结束连接**：关闭 SSM 会话，清理进程环境中的密码和临时文件。
8. **复核报告**：检查报告是否把只读查询写成了业务签字、部署确认或端到端完成。

## 输出格式

```text
问题：
范围：
环境：
访问方式：
已观察事实：
已确认结论：
未验证事项：
阻塞项：
证据位置：
```

## 失败处理

- 隧道失败：记录 AWS profile、region、目标类型和错误类别，不记录凭据。
- 账号或 schema 不符：停止查询并标记 `blocked`。
- 查询超时：缩小时间范围或字段范围，不提高权限绕过限制。
- 发现写入需求：转为独立的变更评审流程，不在只读核查中执行。
