# 共享工作原则

## 工作方式

- 先确认任务目标、范围、输入和完成标准，再开始修改。
- 区分已观察、已确认、建议、已完成、阻塞、待确认和未验证的内容。
- 外部系统的只读观察、代码自测和推断不能直接表述为业务签字或生产确认。
- 对未知值保留未知，不凭空补全关键事实。
- 处理订单、计费、奖励、退款或生产数据时，分别记录事实、归因、资格、状态、账务和外部提供方结果。

## 规则优先级

当前用户指令、平台安全约束和项目规则优先于本文件；本文件优先于 agent 的临时推断。

## 变更方式

- 正式规则只在共享仓库中维护。
- agent 产生的新长期信息先写入 `inbox/`，不要直接覆盖正式记忆。
- 变更必须带来源、范围、日期和置信度。
- 发现冲突时保留两边证据，标记 `pending_confirmation`，等待确认。

## 安全边界

- 不在仓库中写入密钥、密码、生产连接串、令牌或未脱敏的客户个人数据。
- 不因共享规则而自动执行外部发送、支付、退款、发布或其他不可逆操作。
- 所有工具能力和平台限制以当前环境为准，不假设其他 agent 拥有相同权限。
